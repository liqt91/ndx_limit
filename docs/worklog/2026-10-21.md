## 二、首屏装饰带（主任务，5 轮迭代）

### 需求本质：这是背景，不是图表

用户原话「抽象的就行，不用显示精确数额，更侧重与页面风格的融合」。整个迭代过程验证了一件事：**这类装饰的任何解释性元素都是噪音**——初版加了微图例（「近 N 个交易日 / 开门数 / 可投额度」），用户反馈「感觉有点乱」，删掉图例和顶点刻度线之后立刻干净了。教训：装饰性视觉只保留形状，不配任何文字。

### 组件：`src/components/TrendBackdrop.astro`

- 数据：`loadDailySummaries(30).reverse()` 取近 30 个交易日（当前 22 个有点），口径与结论句一致（人民币、按组成组、组内任一可买即开门、可买份额限额相加）。少于 2 个点整体不渲染。
- **两条指标各自按自己量纲归一**：开门数 7–13 家 vs 可投额度 135–1084 元，差两个数量级，同轴会把前者压成直线。
- 家数 = 实心柱（从基线长出），申购额 = 虚线（压柱而过）；viewBox 1000×128，`preserveAspectRatio="none"` 横向拉伸 + `vector-effect="non-scaling-stroke"` 保线宽。
- 动画：柱 `scaleY` 从基线长出（按天错开 14ms），折线延迟 0.35s 淡入；`prefers-reduced-motion` 全关。
- `aria-label` 写「近 N 个交易日的开门数与可申购额度走势」——屏幕阅读器可见，视觉不可见。

### 迭代史

| 轮次 | 形态 | 触发 |
|------|------|------|
| 1 | 双折线 + 微图例 + 顶点 1px 刻度线 | 初版 |
| 2 | 删图例、删刻度线、线带上移到标题 glyph 上方 | 「感觉有点乱」 |
| 3 | 改柱状（每天两根细柱） | 「改成柱状图看看呢」 |
| 4 | 改组合图：家数 = 柱、申购额 = 虚线 | 「家数用柱状，申购额用折线」 |
| 5 | 成为标题区通栏背景 + 渐变蒙版 + 标题下沉 | 「淡一点，上端和标题对齐，下端不动」「作为标题的背景」 |

### 位置终局：CSS Grid 通栏背景

`.masthead` 改为 Grid：装饰带 `grid-row/column: 1/-1` + `z-index:-1` 跨满全部文字行——顶端与标题顶边对齐，底端停在注释行下方原来的位置。文字三项必须显式 `grid-column:1`，否则会被自动放置挤进隐式第二列（截图里文字整个跑到了右边，踩过）。

### 视觉终态

- 透明度三档：柱 0.32 / 线 0.24 / 基线 0.16（窄屏再淡一档）。
- 左→右渐变蒙版：`linear-gradient(90deg, rgba(0,0,0,0.18) 0%, #000 90%)`——左侧约九成是淡入过渡，只有最右端显形（用户：「左边淡的区域再多一点」，升满点 55%→78%→90% 三次右移）。
- 标题逐次下沉：网格顶部留白 20→34→48px，底部占位等量收缩（固定行总量 58 不变，装饰带自身位置不动）。
- 单一墨色、发丝细线，不引入彩色——与全站「纸感」一致。

### 极端数据压测：噪声下限 floors

临时页压测 5 场景 × 有/无下限两版：

- **唯一翻车场景**：全极低微波动（0↔1 家 / 0~30 元）——自归一把 ±1 家放大成满带尖峰 + 剧烈锯齿线，看起来像渲染出错。
- 其余场景（全零、个别极高、全极高）形状均可接受。
- 修复：组件加可选 `floors` prop（`{opened, total}`），`span = max(max-min, floor)`；首页传 `{opened:3, total:200}`（家数按 17 组口径、额度按百元级波动）。
- 真实数据跨度（约 6 家 / 949 元）远大于下限，**首页几何与修复前逐像素一致**（用 dist 路径数据断言验证）。
- 备选方案否掉：全时间固定参考尺——历史仅 22 天、全时间峰值即窗口峰值，会把已确认的满带形态压成半带以上。

## 三、数据 bug：loader 聚合错位（可投总额漏算）

`loadDailySummaries` 与 `aggregateForDate` 把 status 与 limit 分压两个数组，而「暂停份额（limit=null 不进 limits）排在限额份额之前」时索引错位、整条漏算额度。实测 2026-09-14~18 可投总额少 100 元（984 → 1084）。

**修法**：entries 成对收集后过滤求和。首页装饰带与 /daily 快照口径因此一致。

## 五、备选信息源调研：新浪否决，晨星接入

用户问「新浪、晨星有没有限购金额信息，有的话作为备选信息源」。结论一否一接：

### 新浪——字段齐全，但数据滞后，否决

- 字段确实有：`FdFundService.getDealRule` 的 `subscribe_state`/`max_buy`、`getFundBuyStatus2` 的 `trade_limit`；JSONP 无反爬。
- 但**时效不行**：040046 暂停后仍显示「可申购 5 元」、019441 当日调限额后仍显示无限制；60 只仅 14/60 与天天基金一致。作为兜底源会引入过期错误，不接。

### 晨星——时效好，接入为旁路③

- `morningstar.cn/fund/<6位代码>.html` 直接用基金代码，无需 ID 映射。
- 头部 `.basic-title`/`.basic-value` 结构里有「申购状态」（可申购/限大额/不可申购）+「单日申购限额」，另有分渠道限额（个人代销/直销/机构）；040046 暂停次日即更新。
- **必须带全 UA + Accept + Accept-Language 三头，否则 403**（缺头 403、带齐 200）。
- 全量比对：51/60 与详情页一致；7 处差异均可解释（021000/022525 主链路特例覆盖、4 个美元份额晨星显示限 1 美元、019442 金额 5 vs 10、2 只无数据）。

### 落地

- 新增 `scripts/ms-fallback.mjs`：`fetchMorningstar` / `parseMorningstar` / `msStatusToLocal`。
- `scrape.mjs` 接入为旁路③，兜底链改为：东财详情页 → 全量快照 → 晨星 → UNKNOWN；每日对账写 `fetch-meta.json` 的 `ms` 字段（`--no-ms-check` 可关）；**晨星兜底不计入健康门禁**（它只是旁路，不该影响主链路健康分）。

## 六、踩坑记录

### CSS Grid 隐式列陷阱

装饰带作为 Grid 子元素被自动放置挤进了隐式第二列（SVG 固有宽度把第一列撑窄后，文字全跑右侧）。修法：`grid-template-columns:100%` + 文字三项显式 `grid-column:1`。

### `preserveAspectRatio="none"` 下圆点会被压扁

顶点圆点标记在横向拉伸下变成椭圆，改用 1px 垂直刻度线（只受 scaleY 影响）——后来刻度线整体删除（见第二节），但这个坑本身值得记。

### 晨星解析正则：alternation 要长的在前

「1 万美元」被「元」的分支先匹配，解析成 1 元。单位 alternation 必须「万美元/万/千」排在「元」前。

### 截图工具的两个缓存问题

deviceScaleFactor 设置不生效、浏览器会话不跨 Bash 调用保持。做法：单元素截图；open + 操作链放在同一条命令里。
