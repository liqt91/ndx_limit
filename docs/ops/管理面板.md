# 运维面板：轻量云上的集中管理位

## 它是什么

一个跑在腾讯轻量云（`lhins-0ky4jsqs`）上的单页服务，把「EdgeOne 调度 → GitHub Actions →
数据/站点/订阅」整条链路聚在一页，并能手动触发。**只听 `127.0.0.1`，不对公网开放**，
访问靠 SSH 隧道——安全边界就是 SSH 本身，所以面板不需要登录态。

代码在仓库 `scripts/ops-panel/`（单一来源）：

| 文件 | 作用 |
|---|---|
| `server.mjs` | 面板服务本体，零依赖（仅 Node 内置模块），Node ≥ 18 |
| `gh-dispatch.sh` | dispatch 触发脚本（本地兜底路径；主路径已换成 EO 端点，见下） |
| `smoke.mjs` | 冒烟测试，零外部网络，`node scripts/ops-panel/smoke.mjs`（65 条断言） |
| `ops-panel.service` | systemd unit（部署件） |

## 全流程监控是怎么拼起来的

crontab 退役之后，链路各段的状态来源如下（★ 当前尚未退役：EdgeOne 未上线，生产调度仍是
本机 crontab，面板的「本地日志」降级视图此刻反而是真源）：

| 链路段 | 面板数据来源 |
|---|---|
| EdgeOne 调度（今天四跳触没触发、事件流、今日被拒次数、告警发没发） | `GET https://qdii.liqt91.top/api/jobs/status`（只读边缘函数，读 KV 事件流水与拒绝计数；`jobs` 按 job × slot 双层返回，refresh 三档 `preopen`/`intraday`/`close`，broadcast 两档 `morning`/`close`） |
| workflow 运行 | GitHub API（PAT，服务器 `/root/.gh_dispatch_token`） |
| 数据新鲜度 | `raw.githubusercontent.com` 的 `data/fetch-meta.json` + 最近数据 commit |
| 订阅数 | 站点 `/api/subscribers`（`SUBSCRIBERS_TOKEN`） |
| PAT 到期 | 本地 `/root/.gh_dispatch_token.meta.json` |
| 手动触发 | **优先** POST 站点 `/api/jobs/dispatch`（带 `EO_CRON_SECRET` 与按当前时刻就近落槽的 `slot`/`edition`：过午手点 broadcast 发的是收盘前报）；未配则回退本地 `gh-dispatch.sh` |

EO 端点不可达时自动降级读本地 dispatch 日志（crontab 时代的旧记录），页面会标注
「本地日志（降级）」并给 note——看得见降级，不会把旧日志当成今天的成绩。本地日志没有
slot 字段，按**落点时刻**归槽（09:00 前算盘前、09:00–12:00 算早盘、之后算收盘前；
broadcast 只看 12:00 分界），不是按出现顺序——三个抓取时点用顺序分配会把退役前 14:30
那条错标成「早盘」。无条目的槽位显示「未知」而不是「缺失」——退役后日志停更，
「没有记录」不等于「没有触发」。

## 安全模型

- **只听回环**：默认 `127.0.0.1:8780`。启动时校验监听地址，只放行回环与 Tailscale 段
  （`100.x`），配成 `0.0.0.0` 会**拒绝启动**（exit 3）——宁可起不来，不误暴露。
- **无登录态**：能连上 `127.0.0.1:8780` 说明流量已经过了 SSH 这一关，再加一层登录只是
  自己麻烦自己。
- **真发信二次确认**：broadcast `send` 必须在弹窗输入 `send` 才会提交（前端确认 + 后端
  `confirm=send` 双重校验，缺一返回 400）。EO 端点那头还有一层每日闸 + nonce，双保险。
- **审计日志**：所有面板触发写入 `/var/log/ops-panel-audit.log`（JSON 行，含 `via` 字段
  区分 `edgeone` / `script` 两条触发路径），手动发信可追溯。
- **`EO_CRON_SECRET` 是面板唯一的 EO 侧密钥**：存服务器 `/root/.eo_cron_secret`（`chmod 600`）
  或 systemd 环境，值必须与 EdgeOne 控制台的 `CRON_SECRET` 一致。它不进仓库。
- 腾讯云安全组**不要**为 8780 放行；面板不依赖任何入站规则。

## 页面内容

- **调度（EdgeOne）**：今日四槽（07:50 盘前 / 09:40 早盘 / 14:30 收盘前 / 14:45 收盘前报）
  的结果（HTTP 码 + 时间 + 触发方式）、最近告警（发没发）、**今日被拒次数**（含最后一次的
  原因与 job/slot）、调度鉴权是否配置、最近 6 条事件流（带槽位中文标注）。
  ★ 被拒计数不是事件流水：401/403/409/400 一律不进流水，只累加次数——流水只有 50 条，
  被刷时会灌满，把「今天四跳触没触发」的视野冲掉。计数非零不等于出事，但 `lastError`
  能区分「有人在扫」（`unauthorized`）和「自己配错」（`bad_slot` / `slot_not_scheduled`）；
- **workflow 最近运行**：refresh / broadcast 各最近 3 次，含结论、耗时、深链；
- **数据新鲜度**：数据日期、抓取时间、距今、最近一次数据 commit；
- **订阅与凭据**：订阅人数（走 `/api/subscribers`）、PAT 到期剩余天数、最近 3 条审计；
- **手动触发**：立即 refresh（安全）/ broadcast dry-run / broadcast 真发信（二次确认）。
  触发结果里带 `via=edgeone` 即走了 EO 端点。手动触发的 slot 按当前时刻就近落槽
  （09:00 前 `preopen`、09:00–12:00 `intraday`、之后 `close`；broadcast 只看 12:00 分界）。

状态灯口径：`bad` = 今日调度有失败/缺失（EO 事件流里的 502 级失败，或过点未触发），
或最新一次 workflow 结论非 success；`warn` = EO 端点不可达（降级中）、告警邮件上次
发送失败或未配置、`CRON_SECRET` 未配置、数据非今日、PAT 剩 ≤30 天、订阅数取不到、
缺 token 看不见 workflow；`ok` = 其余。每 30 秒自动刷新。

## 部署（服务器上执行，需 root）

WorkBuddy 的 Lighthouse MCP 只放行只读命令，写文件要经 SSH 或轻量云控制台终端。

```bash
# 1. Node 22（Ubuntu 若自带 node 也可，但建议与 CI 同版本）
curl -fsSL https://deb.nodesource.com/setup_22.x | bash - && apt-get install -y nodejs

# 2. 取代码（三件套 + unit）
mkdir -p /opt/ops-panel && cd /opt/ops-panel
for f in server.mjs gh-dispatch.sh smoke.mjs ops-panel.service; do
  curl -fsSL -o "$f" "https://raw.githubusercontent.com/liqt91/qdii_limit/main/scripts/ops-panel/$f"
done
chmod 755 gh-dispatch.sh
cp ops-panel.service /etc/systemd/system/ops-panel.service

# 3. 凭据（复用已有文件；订阅 token 从 EdgeOne 项目环境变量里拿，与 GitHub Secrets 一致）
install -m 600 /dev/null /root/.subs_token   # 若已存在则跳过，把 SUBSCRIBERS_TOKEN 写进去
# EO 侧手动触发密钥（可选但推荐）：与 EdgeOne 控制台 CRON_SECRET 同值
install -m 600 /dev/null /root/.eo_cron_secret && echo -n '<CRON_SECRET>' > /root/.eo_cron_secret

# 4. 环境文件（可按需改端口；EO_STATUS_URL 默认由 SITE_ORIGIN 推导，一般不用写）
cat > /etc/ops-panel.env <<'EOF'
PANEL_HOST=127.0.0.1
PANEL_PORT=8780
GH_DISPATCH_TOKEN_FILE=/root/.gh_dispatch_token
SUBSCRIBERS_TOKEN_FILE=/root/.subs_token
EO_CRON_SECRET_FILE=/root/.eo_cron_secret
EOF

# 5. 起来 + 开机自启
systemctl daemon-reload
systemctl enable --now ops-panel
systemctl status ops-panel
journalctl -u ops-panel -f        # 看日志
```

PAT 到期展示：把 `{"issuedAt":"...","expiresAt":"..."}` 写进 `/root/.gh_dispatch_token.meta.json`
（签发 PAT 时顺手记），面板才会显示剩余天数；不写则显示「未登记」，不影响其它功能。

## 访问

```bash
ssh -L 8780:127.0.0.1:8780 root@123.206.104.183
# 保持这个 SSH 会话，浏览器开 http://127.0.0.1:8780
```

- 手机：Termius / Blink 等 SSH 客户端都支持端口转发，同样开 `http://127.0.0.1:8780`。
- 不想每次建隧道：给服务器装 Tailscale，`PANEL_HOST` 改成它的 `100.x` 地址即可
  （启动守卫放行该段）；仍不进公网。

## 服务器上的面板怎么改（2026-10-21 起）

仓库 `scripts/ops-panel/` 是单一来源，服务器 `/opt/ops-panel/` 是部署副本。改面板
**只改仓库，然后同步**，别直接改服务器上的文件（会漂移，下次同步覆盖还没处说理）。

方式 A（服务器装了 git，推荐）：

```bash
cd /opt/ops-panel && git pull && systemctl restart ops-panel && journalctl -u ops-panel -f
```

方式 B（没装 git，按部署时的 curl 方式）：

```bash
cd /opt/ops-panel
for f in server.mjs gh-dispatch.sh smoke.mjs ops-panel.service; do
  curl -fsSL -o "$f" "https://raw.githubusercontent.com/liqt91/qdii_limit/main/scripts/ops-panel/$f"
done
chmod 755 gh-dispatch.sh
cp ops-panel.service /etc/systemd/system/ops-panel.service
systemctl daemon-reload && systemctl restart ops-panel
```

改了 `EO_CRON_SECRET` / 端口等配置只动 `/etc/ops-panel.env`，重启即可，不用重新拉代码。

## 与定时链路的关系

- crontab **尚未退役**（2026-10-21 16:45 实测仍在跑 07:50 / 08:10）：定时触发目前仍由本机
  crontab 代发。EdgeOne `schedules` 验证通过后才删；那之后服务器上只剩这个面板，即使整机宕机，
  每日抓取/发信照常，只是面板打不开。
- 面板的手动触发优先走 EO 端点（`EO_CRON_SECRET`），服务器 PAT 过期也不影响能触发；
  每次点击还顺带验证 EO 这条路径是活的。`DISPATCH_VIA=local` 可强制回退本地脚本。
- 本地 `gh-dispatch.sh` 保留作最后兜底：EO 端点整体故障时，`ssh` 上去
  `/usr/local/bin/gh-dispatch.sh refresh` 手动补一次（期望 204）。

## 故障排查

| 现象 | 先看哪 |
|---|---|
| 面板起不来，日志「拒绝启动」 | `PANEL_HOST` 配错了，只允许回环或 `100.x` |
| 调度卡片显示「本地日志（降级）」 | EO 端点不可达：`curl -s https://qdii.liqt91.top/api/jobs/status`；站点整体故障时订阅/首页同样受影响 |
| 调度卡片显示「无数据源」 | EO 不可达且本地日志也没有（全新部署 or 日志被清） |
| workflow 卡片显示「不可见」 | 缺 `GH_DISPATCH_TOKEN`（文件或环境变量） |
| 订阅数显示 token 无效 | `/root/.subs_token` 与 EdgeOne 环境变量里的 `SUBSCRIBERS_TOKEN` 不一致 |
| 手动触发返回 `unauthorized` | `EO_CRON_SECRET` 与 EdgeOne 控制台 `CRON_SECRET` 不一致 |
| 按钮转圈不出结果 | `journalctl -u ops-panel`；EO 端点 90 秒超时 |
| 改完代码不生效 | 确认同步的是仓库最新版，然后 `systemctl restart ops-panel` |

## 变更纪律

1. 改 `scripts/ops-panel/` 下任何文件 → 先在开发机跑 `node scripts/ops-panel/smoke.mjs`
   （65 条断言，覆盖 EO 聚合、降级、告警状态灯、EO 触发路径、二次确认、主机守卫与
   内联脚本编译；负向验证记录见提交历史）；
2. 再按上面「服务器上的面板怎么改」同步到 `/opt/ops-panel/`；
3. `systemctl restart ops-panel`，`journalctl -u ops-panel -f` 确认监听正常。
