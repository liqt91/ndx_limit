## 一、全量快照旁路

一次请求（`Fund_JJJZ_Data.aspx?t=8&page=1,50000`）拿到全市场 27,849 只基金，约 4.2MB、5 秒。
`scrape.mjs` 在逐页抓取前后各用一次：

1. **对账**：把逐页解析出的（可买性 + 金额）与快照比。**金额可信**（2026-10-21 实测 54/54 完全相等），
   所以金额不一致 = 解析可能漂移，写进 `fetch-meta.json` 的 `shadow.mismatch` 并打日志。
2. **兜底**：某只详情页抓失败时，若快照对这只基金的状态不是 UNKNOWN，就用快照补一个点，
   不再直接写 `UNKNOWN`。**兜底的份额不计入健康门禁**——否则上游页面改版时门禁会变成假绿灯。
3. **缺口**：用 `纳斯达克100 / 纳指100 / NASDAQ100` 扫全市场，找出名单里没有的份额。
   **场内 ETF（159/513 开头的「场内交易」）不算缺口**，本站口径只统计场外申购份额。
   缺口只报不改：`funds.json` 要人工维护，自动并入会让口径失控。

**为什么不拿快照当主链路**：它的状态字段有噪声。实测 016055 写「暂停申购」却给
日累计限额 `100000000000`（1e11 是「没设这个字段」的占位值，不是无限额）；021000 写「限大额」，
详情页却是「该基金暂不开放购买」。金额可以用，状态不能。

**安全**：上游返回的是一段 JS 对象字面量。本仓库**不执行**它（`new Function` / `eval` 都不许），
`em-snapshot.mjs` 里手写扫描器把它转成 JSON 文本再 `JSON.parse`。

## 二、双时点抓取

- 时点：`morning`（早间）/ `close`（收盘前）。**按北京时间自动判**：12:00 前算早间，之后算收盘前；
  需要精确指定用 `--slot=close`。之所以不要求调度端传参，是因为触发链路正在迁移，两边同时改容易对不上。
- 同日重复运行仍幂等覆盖当日点；`fetch-meta.json` 新增 `slot` 与 `runs[]`：
  ```json
  { "slot": "close", "runs": [
      { "slot": "morning", "time": "07:51", "opened": 6, "total": 130, "changed": null },
      { "slot": "close",   "time": "14:31", "opened": 7, "total": 135, "changed": [ … ] } ] }
  ```
  `changed` 是「与同日另一次运行比」的差异。history 每个交易日只留最后一个点，早间的值会被覆盖，
  所以这个差异必须在覆盖前后各取一次算出来存这儿，否则收盘前报答不了「上午到现在变没变」。
- 早间那次 `changed` 为 `null`（没有更早的同日运行可比）。

## 三、公告作为解释源

**落哪些字段**（`data/announcements.json`，每只份额最多留 6 条）：

| 字段 | 用途 |
|---|---|
| `id` | 去重键（上游 `ID`，如 `AN202610211830733237`） |
| `date` | 展示「10-21」；**接口只有日期没有时分**，所以不写「上午发布」 |
| `kind` | `limit / suspend / resume / open / cap`，决定文案与配色 |
| `action` | 固定短语（调整大额申购限额 / 暂停申购 / 恢复申购 / 开放日常申购 / 调整规模上限） |
| `title` | 原文标题，详情页展示 + `title` 悬浮兜底 |
| `url` | `fund.eastmoney.com/gonggao/<code>,<id>.html` |

**不落什么**：正文（几万字 PDF/HTML，跟额度无关的多）、`NEWCATEGORY`（不可靠：「取消总规模上限」
是 cat6，「调整大额申购」是 cat5，所以按标题关键词分类）、作者/机构等。

**三类噪声在上游就剔除**（见 `classifyAnnouncement`）：
直销渠道公告（影响直销，不是我们展示的代销口径）、境外节假日临时暂停（是休市，不是限购）、
费率优惠/参加认申购活动（与额度无关）。

**何时抓**：只对「与上一个交易日相比有变化」的份额抓（一天通常 1~4 只，不是 60 只）。
公告发布于抓取之后是常态（2026-10-21 万家 07:51 后发公告、当天额度从 10 元改成 5 元），
所以公告是**事后解释**，不能当抓取的先行信号。

**展示**：首页「今日变化」每行挂一个 `公告 · <动作>` 的小链接（只认 3 天内的公告）；
详情页有「申购相关公告」一节，列最近 6 条。没有公告就不写，不猜原因。

## 四、收盘前报（14:45）

`digest.mjs` 增加 `edition`：

- `morning`：盘前报，人工补发用（2026-10-23 起**默认值已改为 `close`**），末尾加一句「收盘前 14:45 会再发一次当日最终额度」。
- `close`：标题「纳指100 开门日报 · 10-23 收盘前」（多指数时是「QDII 开门日报 · 10-23 收盘前」），正文顺序是
  **当日快照（几家开门/多少元可投，带抓取时刻）→ 较昨日变化 → 较盘前变化 → 今日能买清单（基金代码 + 当日额度）→ 15:00 截止提示**。
  清单一家一行（`宝盈纳斯达克100：A类 019736 10元 · C类 019737 10元`），人民币与美元分两组、不相加；
  暂停 / 封闭 / 当天没数据的份额不进清单。清单里的额度加总必须等于标题里的「合计 X 元可投」——两者是同一份数据。
  场外 15:00 截止，所以这个时点才是「今天还能不能下单」的答案。

`send.mjs`：`--edition=close` 或环境变量 `DIGEST_EDITION=close`。

## 五、运维侧接入（2026-10-21 续章已落地）

触发链路迁往 EdgeOne 后（见《edgeone-迁移.md》L1），调度与 dispatch 由 EdgeOne
`schedules` 代发，本节四项已全部落地。当日写的是「本期故意没动」——那是迁移期的隔离
决策，避免轻量云 crontab 与 EdgeOne 两边同时改打架；crontab 退役、L1 稳定后随即接上。

### 1. `edgeone.json` 四条 schedule（已落地，2026-10-21 下午改为三抓一报）

```json
{ "name": "refresh-0750",   "cron": "50 7 * * *",  "payload": { "job": "refresh",   "slot": "preopen" } },
{ "name": "refresh-0940",   "cron": "40 9 * * *",  "payload": { "job": "refresh",   "slot": "intraday" } },
{ "name": "refresh-1430",   "cron": "30 14 * * *", "payload": { "job": "refresh",   "slot": "close" } },
{ "name": "broadcast-1445", "cron": "45 14 * * *", "payload": { "job": "broadcast", "mode": "send", "edition": "close" } }
```
（每条另有 `timezone: "Asia/Shanghai"`、`path: "/api/jobs/dispatch"`、`method: "POST"`、`nonce`，此处省略。）

**08:10 的 `broadcast-0810` 已删除**：订阅者每天只收一封（14:45）。早间抓取仍在 07:50，
站点数据照样早上更新，只是不再单独发一封早间邮件。`broadcast.yml` 的 `edition=morning`
选项保留，供手动补发**盘前报**（`edition=morning`，需带 `CRON_SECRET`，未鉴权路径已被白名单挡住）。

**09:40 那一跳的作用**：07:50 偏早、单向少报——当日额度调整公告多在 07:51 之后才发
（实测 10-21 漏 2 个份额，而全天平均只变 1.3 个）。盘中额度几乎不动，所以这一抓是
**补早盘公告窗口**，不是追波动。

抓取时点由脚本自己按时刻判定，**不需要**给 refresh 传抓取参数；`slot` 只用于 dispatch
侧分闸（见第 2 条）。14:30 抓、14:45 发，中间 15 分钟覆盖抓取 30 秒 + EdgeOne 重建。

★ 修订记录：
- 本节初版给 `refresh-1430` 的 payload 漏了 `"slot": "close"`。实现时补上——
  漏了它，14:30 的未鉴权调用会撞上早间的闸 key 被 409 挡掉（正是第 2 条要治的病）。
  早间两条也显式写了 `slot`/`edition`，防的是将来有人改默认值时静默踩坑。
- 2026-10-21 下午：refresh 的 slot 由 `morning`/`close` 两档改成
  `preopen`/`intraday`/`close` 三档。**改名是有意的**——两个 morning 抓取共用一个闸键的话，
  09:40 那次必被 409 挡掉。旧名复用会让「09:40 配了但没生效」变成静默故障。
  `scrape.mjs` 的 slot 仍是 `morning`/`close` 两档（按 12:00 自动判），两套不要混：
  前者只管分闸，后者管 `fetch-meta.json` 的记录。

### 2. ★ `dispatch.js` 的闸按版次分键（已落地）

`guardKey = job_sent_${job}_${slot}_${cstDate()}`，`slot` 由 `resolveSlot(job, data)` **显式校验**：
broadcast 看 `payload.edition`（缺省 `close`），refresh 看 `payload.slot`（缺省 `preopen`），
取值不在白名单就 **400 `bad_slot`**——不再「认不出来就当默认值」，否则 slot 写错会静默占掉
另一个时点的闸键。事件流水、告警邮件、面板槽位全部带 `slot`。

未鉴权调用另有组合白名单（403 `slot_not_scheduled`）：只接受调度表里真实存在的
job×slot。盘前报 schedule 下线后 `broadcast/morning` 的闸键虽在，但未鉴权路径会拒掉，
避免匿名者凭空多发一封信。401/403/409/400 都只累加 `job_rejected_<日期>` 计数，
**不写 50 条的事件流水**（流水被噪声灌满 = 监控瞎掉）。

`callGitHub` 同步透传 `inputs.edition`（broadcast）。注意 `workflow_dispatch` 的 inputs
只认已声明的 input——**本条与第 3 条必须一起上线**，否则 GitHub 会以 422 拒掉透传。

### 3. `broadcast.yml` 加 `edition` input（已落地）

```yaml
on:
  workflow_dispatch:
    inputs:
      mode:    { description: '…', type: choice, options: [dry-run, send], default: dry-run }
      edition: { description: 'close 收盘前报 / morning 盘前报', type: choice, options: [close, morning], default: close }
      indices: { description: '留空=按订阅偏好与数据可用性自动决定', type: string, default: '' }
```
Send 步骤的 env 里补 `DIGEST_EDITION: ${{ inputs.edition }}` 与
`DIGEST_INDICES: ${{ inputs.indices || steps.freshness.outputs.usable }}`。

★ 2026-10-23：默认值由 `morning` 改为 `close`（生产的 14:45 那跳就是收盘前报），
并新增 `indices` 输入与门禁输出的 `usable` 串联——`check-freshness` 按指数各判一次新鲜度，
只有可用的指数会进 `DIGEST_INDICES`；有指数被剔除时输出 `degraded=true`，
job 末尾的 `Flag dropped indices` 步骤会把这次 run 标红（漏发不能是绿的）。

## 六、上线后怎么验

1. `gh workflow run refresh.yml`（或等 14:30）→ 看日志末尾有没有
   `✓ 全量快照：27849 只`、`对账：N/N 与全量快照一致`、`名单外只有场内 ETF 3 个`。
2. 首页「数据更新于今日 14:32」；下午打开时若还显示今晨时刻且已过 14:50，
   页面会亮提示「今日午后数据尚未更新，当前是今晨 07:51 的结果」。
3. `node scripts/send.mjs --dry-run --edition=close` 打出来的正文应是「收盘前：… 元可投」开头。
4. 第二天确认 `fetch-meta.json` 的 `runs` 是两条且带 `changed`（当天有变化时）。
5. 运维面板「调度（EdgeOne）」卡应显示四槽（07:50 盘前 / 09:40 早盘 / 14:30 收盘前 /
   14:45 收盘前报），过点后逐槽亮起；事件流每条带槽位中文标注；「今日被拒」非零时看
   `lastError` 判断是有人扫（`unauthorized`）还是自己配错（`bad_slot`）。
6. 若 `shadow.mismatch` 非空：先看是不是我们解析漂移，不要先怀疑上游。
