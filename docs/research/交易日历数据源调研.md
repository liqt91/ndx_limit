# 交易日历数据源调研

- 日期：2026-10-19（调研）/ 2026-10-20（归档）
- 背景：纳指开门日报需要判断「今天是否为交易日」来隐藏非交易日、显示休市态。
  当前实现用本地硬编码的 `data/market-holidays.json`（A 股 2026 官方 + 2027 预设）。
  本期调研目标：**寻找免费、可定期更新的 A 股 + 纳斯达克交易日判断方案**，替代/增强本地硬编码。

## 调研方法

- 对候选的免费 API 与 npm 包逐一**实跑验证**（非纸面），关键日期覆盖节假日、调休、美股 Good Friday /  early close 等边界。
- 验证环境：Node 22（managed runtime），北京时间。

## A 股交易日（中国）

| 方案 | 实测 | 结论 |
|---|---|---|
| **`market.ft.tech` 交易日历 API** | `GET /api/v1/market/data/time/trading-calendar?market=cn&start_date=..&end_date=..` 免密钥，HTTP 200，返回 `trade_dates` 数组（即交易所实际交易日，自动含调休）。2026-10 返回 17 天，正确包含国庆后 10-08/10-09、排除 10-01~10-07。 | ✅ 首选，权威；定期更新 = 上游随年份刷新，CI 每日拉取缓存即可 |
| `date-holidays`（CN 数据） | 实跑漏判：2026-10-07（国庆）、2026-01-02/03（元旦）、2026-02-15（春节首日）均返回「非假日」 | ❌ 不可用，不能用于 A 股 |
| 上交所官网「休市安排」页 | 有数据但是网页非 API，难解析 | 仅兜底 |

> ⚠️ 短板：ft.tech 免费版当前仅覆盖 **2000-01-04 ～ 2026-12-31**，实测 2027-01 返回 `400 仅支持至20261231`。2027 需上游扩覆盖或加兜底。

## 纳斯达克交易日（美股）

| 方案 | 实测 | 结论 |
|---|---|---|
| **`us-equity-market-calendar`（npm）** | 算法型、零依赖、任意年份。Good Friday(2026-04-03)=false、Independence observed(2026-07-03)=false、感恩节次日 early close 算交易日、`previousTradingDay` 正确；2027 年同样正确。 | ✅ 首选，无需联网、无需维护数据；定期更新 = `npm update` |
| `howmanytradingdays.com/api` | 免密钥、无频率限制，返回 `isOpen / isTradingDay / nextSessionDate` | ✅ 免费 API 备选 |
| `date-holidays`（US 数据） | 给的是美国联邦假日——缺 Good Friday、多算 Columbus/Veterans Day，与真实股市日历不符 | ❌ 不可用 |

## 结论与推荐

1. **A 股**：采用 `market.ft.tech` 交易日历 API。在 `refresh.yml` 中加一步拉取「未来 ~400 天」交易日并缓存到 `data/cn-trading-days.json`；构建读本地文件（离线安全），拉取失败回退到现有 `market-holidays.json`。
2. **纳指**：引入 `us-equity-market-calendar` npm 包替代手工维护的美股部分，`npm update` 即更新。
3. **兜底**：保留 `data/market-holidays.json` 作为 ft.tech 不可用 / 2027 缺口时的兜底。

## 待决事项（需用户拍板）

- **纳指日历的角色**：本项目是「纳指 QDII 在**中国**的申购日报」，判定「能否申购」实际取决于**中国 A 股是否开市**（国内平台下单）。纳指历是次级信号（美股休市时净值不更新、基金可能暂缓建仓）。两种接法：
  - (A) 仅展示：A 股历驱动「是否交易日」判定，纳指历只在页脚加「美股今日休市」提示；
  - (B) 双重判定：中、美任一方休市都视为「今日申购受限」，首页相应降级。
- **ft.tech 2027 缺口**：是否保留本地 `market-holidays.json` 兜底（推荐保留）。
